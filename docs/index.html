Payments · acquirer underwriting · Snowflake example

Every new merchant gets a decision you can defend.

Underwriters approve, refer or decline new merchants all day, then have to explain each call to credit committee. This example scores every application 0 to 100 from five visible factors, sets the reserve, and writes underwriting notes that a second model pass checks against the allowed numbers, all on Snowflake.

Every one of the pack's 720 synthetic applications, one tick each, at its risk score. Under 40 approves, 40 to 69.9 refers to an underwriter, 70 and over declines.

The problem

A risk score nobody can explain is hard to act on, and a written summary with one wrong number is worse than none.

5

Factors, shown for every merchant

Category base risk, chargeback history, credit tier, years trading and a prior-processor switch add up to the score. The drawer shows each contribution.

40 / 70

Thresholds, applied the same way every time

Approve under 40, refer from 40, decline at 70, with a decline reason and a reserve set by rule in SQL.

2 passes

Notes that are checked, not trusted

Cortex AI_COMPLETE drafts from a fact pack; a second call fact-checks every figure and badges the note Verified or Needs review.

How Snowflake does each step

Everything below ran Live in a Snowflake account during the build, with key-pair authentication.

StepSnowflake featureMeasured
Score, decide, reason and reserve every applicationSQL views and a CTAS table (MERCHANT_RISK_SCORE_FACTORS, MERCHANT_RISK_DECISION)Whole setup 17 s on XSMALL
Portfolio, queue and segment screensSnowpark Python session reading MERCHANT_RISK_BOOK and the CFPB backdrop tableAbout 2 s first load
Grounded underwriting noteCortex AI_COMPLETE (claude-sonnet-4-5): draft, then verify against the fact pack9 to 19 s per note
Plain-English questionsCortex Agent (DATA_AGENT_RUN) with Cortex Analyst over a semantic view8 to 27 s per answer
Run the app inside SnowflakeStreamlit in Snowflake, warehouse runtimeCREATE STREAMLIT from a stage succeeded

The application book and, by default, the CFPB backdrop are synthetic. sql/cfpb_live_backdrop.sql swaps in the free CFPB Complaint Database from Snowflake Marketplace; that script was not run in this build because the listing was not mounted in the test account.

Run it

No account: Sample mode

Open the hosted example, or run the Streamlit app on the bundled synthetic data:

pip install -r app/requirements.txt
streamlit run app/streamlit_app.py

Your account: Live mode

Run sql/setup.sql in Snowsight, then start the app with key-pair auth or deploy it as Streamlit in Snowflake. Steps in the README. Remove everything with sql/cleanup.sql.

export SNOWFLAKE_ACCOUNT=<org-account>
export SNOWFLAKE_USER=<YOUR_USER>
export SNOWFLAKE_PRIVATE_KEY_PATH=~/.snowflake/keys/<key>.p8
streamlit run app/streamlit_app.py

Cost. Setup runs about 17 seconds on an XSMALL warehouse that suspends after 60 s. Each note makes two AI_COMPLETE calls and each question one agent run; those are billed as Cortex AI tokens. See the README for details.
